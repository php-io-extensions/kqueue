# Scope

macOS `kqueue(2)`, 1:1, plain C on the Zend API: `kqueue()`, `kevent()`, `kevent64()`, `EV_SET()`, `EV_SET64()`, `kqueue_errno()`, three final classes mirroring `struct kevent`, `struct kevent64_s` and `struct timespec`, and the `<sys/event.h>` constants. No event loop, no wrapper, no throwing on a failed call.[^kqueue-c]

macOS only, not BSD: `config.m4` requires `kevent64()`, which only Darwin has, and `composer.json` lists `os-families: [darwin]`. 64-bit only: the C refuses to compile when `SIZEOF_ZEND_LONG != 8` because `kevent64_s` carries 64-bit fields.[^config][^composer][^kqueue-c]

Sibling extensions: ext-epoll (Linux), ext-posi (POSIX calls).

# Module globals

One field, `last_errno`. GINIT zeroes it and updates the TSRM cache under ZTS; RINIT zeroes it again per request. No RSHUTDOWN: nothing outlives a call.[^header][^kqueue-c]

# Struct classes

`kevent`, `kevent64_s` and `timespec` are `final`, `@strict-properties`, with typed `int` properties read and written by slot number (`OBJ_PROP_NUM`) in stub order. `kevent64_s` has a custom `create_object` so `$ext` starts as `[0, 0]`, which the stub cannot declare. See [structs](/api/structs.md).[^kqueue-c]

# Sockets support

`KQ_HAVE_SOCKETS` is defined only when `ext/sockets/php_sockets.h` is present **and** `HAVE_SOCKETS` says ext/sockets is built (inside php-src the header exists either way). The `Socket` class is resolved by name from `CG(class_table)` at call time, never by linking, so `kqueue.so` loads with or without ext/sockets. Without `KQ_HAVE_SOCKETS` a `Socket` ident is a `TypeError`. No `ZEND_MOD_OPTIONAL`: the module entry uses `STANDARD_MODULE_HEADER` with no dependency list, since `Socket` is looked up lazily.[^kqueue-c]

# Errno convention

`kqueue()`, `kevent()` and `kevent64()` return what C returns; on `-1` the errno is saved into `last_errno` for `kqueue_errno()`. On `-1` the `$eventlist` reference is left untouched. Nothing throws for a kernel error. The extension registers ten `E*` constants from `<errno.h>` so callers can compare without another extension.[^kqueue-c]

# Argument convention

PHP-side validation throws before the syscall; kernel-side validation returns `-1`:

| Check | Throws | Where |
|---|---|---|
| `$kq` outside C `int` | `ValueError` | `kq_check_call()` |
| `$nchanges` < 0, > count(`$changelist`), or > `INT_MAX` | `ValueError` | `kq_check_call()` |
| `$eventlist` not `null` or array | `TypeError` | `kq_check_call()` |
| `$nevents` < 0 or > `INT_MAX` | `ValueError` | `kq_check_call()` |
| `kevent64()` `$flags` outside `int32..uint32` | `ValueError` | `kq_range()` |
| changelist entry not the right class | `TypeError` naming the position | `kevent`/`kevent64` |
| struct field unset | `Error` (typed property uninitialised) | `kq_read_long()` |
| `filter`/`flags`/`fflags` wider than their C field | `ValueError` naming argument or property | `kq_check_narrow()` |
| `$ident` not int, stream resource, or `Socket`; closed stream; closed `Socket` | `TypeError` / `ValueError` | `kq_zval_to_ident()` |
| `kevent64_s::$ext` not exactly `[int, int]` at keys 0 and 1 | `ValueError` / `TypeError` | `kq_kevent64_from_object()` |

Narrow fields accept either the signed or the unsigned reading of their width (`filter`: `INT16_MIN..UINT16_MAX`), as C's implicit conversion does; they are stored back as the C type holds them (`0xffff` flags stay `0xffff`, `-1` filter stays `-1`). Streams are cast with `PHP_STREAM_AS_FD_FOR_SELECT | PHP_STREAM_CAST_INTERNAL`.[^kqueue-c]
